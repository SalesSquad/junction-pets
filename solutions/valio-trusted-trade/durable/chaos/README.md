**Known WAL qualification failure (not a PASS):** [CRACI run #43629641895](https://github.com/SalesSquad/junction-pets/actions/runs/43629641895), source `18718e877d9083abc3f89c94793ed2bf65e3e694`, artifact `14128170014`, failed at the deliberate server SIGKILL. Its captured `child.stderr.log` shows eight Node `Unhandled 'error' event` crashes, all with `Connection terminated unexpectedly` from checked-out `pg` Clients. This is an application-side crash handling bug: `pg-pool` removes the idle error handler while a Client is checked out. The follow-up adds a dedicated WAL worker and permanent Client/Pool error listeners. All eight workers explicitly acknowledge a *narrow* expected-SIGKILL window before the postmaster is killed; unexpected SQL/provider error codes still fail the lab. The above red receipt remains intact. A new real PostgreSQL CRACI run is required to qualify the repaired source; local Node checks alone are not such a qualification.

**Further fail-closed review gate:** An independently identified risk was that `Promise.allSettled` of the eight in-flight transactions was awaited but its results discarded. That could permit a worker-reported, unrelated SQL `42P01` failure to be mistaken for an intentional interruption and later hidden by successful replay. The lab now audits **all eight positional IPC outcomes** before restart, admitting only (1) a successful, first-time committed settlement, (2) an explicitly recognized PostgreSQL disconnect during the authorized crash, or (3) a terminated owned child with verified `SIGKILL` (including its IPC channel closure). Any other SQL/provider result, unexpected process death, missing outcome or mismatched count refuses qualification. Tests inject `42P01` inside the crash window and verify refusal; these Node tests do not replace a real WAL CRACI run.

**Meaningful change:** test actual OS/storage death and Write-Ahead Log recovery, rather than repeatedly running already-green in-memory fixtures or falsely simulating a crash with an HTTP 500. This tool creates a **new disposable PostgreSQL cluster in a private random temporary directory**, listens only on a private UNIX socket, with `fsync=on`, `synchronous_commit=on`, `full_page_writes=on`. It verifies the exact PostgreSQL postmaster's `/proc` executable and PGDATA path before SIGKILL. It never connects to or stops a pre-existing host service or external database.

## Source-pinned manual CRACI entrypoint

Preconditions: non-root Linux executor, Node 22+, PostgreSQL server tooling (`initdb`, `pg_ctl`, `postgres` for 14–18), parent `durable/package-lock.json` npm dependencies. No Docker, service account password, runtime provider key, production PostgreSQL, sponsor API or persistent filesystem required.

```sh
cd solutions/valio-trusted-trade/durable
npm ci --ignore-scripts --no-audit --no-fund
node --test chaos/test/*.test.mjs
node chaos/wal-lab.mjs --allow-kill9 --workers 8 --requests 10000 --seed 20261114 --max-minutes 23
```

The command explicitly requires `--allow-kill9` and will refuse root/non-Linux hosts. A job-local Ubuntu package install may expose binaries under `/usr/lib/postgresql/16/bin` (discovered automatically), or pass a **verified installed** absolute `VALIO_PG_BIN_DIR`. It does **not** use `VALIO_TEST_DATABASE_URL` because it owns and provisions its own test-only cluster. Pass `CRACI_SOURCE_SHA` from a verified checkout for an informational, source-bound job log; the harness cannot independently prove GitHub checkout authenticity.

Runtime controls: `--requests` even 200–10000 (default 10000), `--workers` 3–8, `--max-minutes` 5–25 (default 23), optional `--keep-data` for test-owned crash forensics. Default **successful** cleanup stops and removes only this invocation's exact `j26-valio-wal-*` temporary cluster. **On every failure**, the harness records a named failure stage, bounded last-64-KiB PostgreSQL log tail (at most 32 sanitized diagnostic lines), SQLSTATE when available, tail digest and owned PGDATA path in stderr, then stops the dedicated cluster and **retains its exact test-owned directory** for forensic inspection. If PostgreSQL cannot be proven stopped, it preserves that directory instead of deleting uncertain state. Do not copy raw PGDATA or logs into public catalogs. CRACI retains wrapper stderr as the source-bound failure receipt; disk-local artifacts remain ephemeral unless the runner explicitly persists them.

## Proof sequence

1. Create a unique PostgreSQL cluster and private socket. Start eight distinct Node worker OS processes against its own fresh `j26_*` schema. Post two acknowledged synthetic order commits.
2. Commit another order, kill its *Node worker* after PostgreSQL COMMIT but before its IPC acknowledgment. Record the ambiguity.
3. Install a temporary test-only eight-second `pg_sleep` trigger for eight distinct flight orders. Inside the trigger, bind each waiting backend's transaction-local `application_name` to the **run-specific schema marker plus actual `NEW.order_id`**. Observe **all eight different PostgreSQL backend PIDs**, exactly eight expected flight markers, `PgSleep`, active state and the correct parameterized ledger-batch `INSERT` query in `pg_stat_activity`. If even one is absent within six seconds, **fail without SIGKILL**. Only then kill the verified isolated PostgreSQL postmaster (and its separately verified subprocesses). No host/other service process is targeted.
   After observing the eight backend PIDs, the coordinator requires a separate IPC `expectCrash` acknowledgment from each of its eight OS workers. Only connection-termination errors *during this verified kill window* may be classified as expected; the same error before this window or unrelated SQL failures at any time are not silently accepted.
4. Restart exactly the same PGDATA/WAL, check new postmaster PID, actual PostgreSQL interruption/redo log signals, and balance/outbox invariants. Replay the acknowledged + ambiguous operations and all flight keys. Require exactly 11 durable orders/batches/outbox rows, independent of how many flight commits survived the crash.
   The preceding eight interrupted operations' individual statuses are all audited and counted before restart; later replay is never used to erase an earlier unrelated SQL failure.
5. Preserve **four adversarial SQL tamper controls** against a WAL-recovered sealed batch: outbox DELETE, mutation, TRUNCATE and unbalanced late INSERT must each return SQLSTATE `23514`, with no altered audit.
6. Execute 10,000 **distinct state-changing** requests: 5,000 uniquely keyed, frozen supplier payment intents followed by 5,000 distinct compensating refunds (some multi-supplier), with a deterministic fixture seed and a fixed cap on execution time. Require exactly 10,011 batches and 10,011 outbox records, 5,011 distinct settled orders, 5,000 refunds, zero negative balances and zero unbalanced batches. No repeated unchanged green requests are counted toward 10k.

JSON output includes measured duration, immutable fixture plan digest, actual PostgreSQL version, owned pre/post-restart postmaster PIDs, **all eight observed flight backend PIDs and query/fixture-marker evidence**, WAL recovery markers and log digest, replay observations and aggregate ledger/outbox invariants. CRACI wrapper must pin the exact GitHub source/workflow SHA separately and retain the real runner job URL/cost (actual provider bill may remain unknown). A local Node contract test **does not qualify** the WAL recovery; only the real isolated PostgreSQL job can.

**Trust boundary:** All orders, approvals, buyers, suppliers and euro balances are synthetic. No live buyer identity, legal mandate, bank movement, supplier order, production Postgres or external exactly-once outbox delivery. Killing a test-owned PostgreSQL postmaster validates local crash/WAL recovery only, not distributed consensus or disaster recovery across hosts.
