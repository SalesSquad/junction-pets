# Recovery Compass — voluntary wellbeing after treatment

**Junction 2026 M343 · Aalto `aalto` partner key · synthetic product milestone 2/6.** Beyond the Clinic is specifically about supporting people at home after depression/TMS care. This is a **general wellbeing interaction prototype**, not maintenance TMS, a device delivering medical care, therapy, relapse prediction, emergency monitoring or a clinically validated recommendation engine. It does not use the separate Aalto Humanoid M320 dataset, or the publicly discussed OpenNeuro EEG sample as supposed treatment evidence.

## Actual runnable user journey

1. User selects a self-described energy preference and voluntarily chooses one of four low-risk, generic support actions (short pause, light movement, connecting with a chosen person, daylight).
2. No diagnosis, symptom score, mood surveillance or risk inference is calculated; the suggestion is exactly the user's own selected action.
3. User explicitly decides to choose the action. No sensor, smartphone function, clinician notification or external service activates.
4. Optional **preview** shows precisely the small whitelist of fields that *could* go in a wellbeing discussion; the interface requires a separate positive opt-in to create a **local unsent draft**. It never sends anything or persists the draft.
5. **Revoke** discards the local draft. **Erase session & capsule** clears memory and attempts local ciphertext deletion, reporting storage failures separately. A crisis guidance disclosure is visible and includes the Finnish 112 emergency number for immediate danger; the app does not triage emergencies.

## M2 encrypted local capsule

Choose an action first, separately check the local-save opt-in, optionally include the coarse energy preference, enter a user-kept passphrase, and press **Save / replace capsule**. Reopen the same browser profile and exact origin (including port), enter the passphrase, and press **Explicitly unlock saved capsule**. No automatic restore occurs. A saved view is separate from today's session: it cannot authorize a share draft. **Lock saved view** and `pagehide` clear its display; **Delete saved capsule**, **Revoke & clear draft**, and **Erase session & capsule** delete ciphertext. Erase clears memory even if the browser denies deletion; the status must report that failure. Retrying deletion remains available.

`src/vault.mjs` uses dependency-free WebCrypto AES-GCM-256 with a fresh secure 12-byte IV and 16-byte salt for each save, PBKDF2-SHA256 with 210,000 iterations, non-extractable derived keys and fixed purpose/version plus exact-origin authenticated context. Only an action ID, optional coarse preference and duplicated authenticated creation/expiry times are encrypted. The strict storage envelope has exactly version/context/iterations/times/salt/IV/ciphertext; no key, passphrase, session, draft, recipient or consent object is persisted. Unlock rebuilds a verified snapshot via `newSession` → `checkIn` → `chooseAction` and never assigns it to current sharing authorization. Save, delete, inspect and unlock immediately request the same origin-wide exclusive Web Lock (`aalto-m343-capsule-v1:storage`) via `navigator.locks.request`. Save holds it from before encryption through IndexedDB transaction completion; deletion waits for earlier saves to commit, then deletes under that lock. There is no nested locking or per-tab mutex fallback. This constraint applies to cooperating tabs running this implementation; an older tab or other same-origin code that ignores the lock can still write. A later explicit save can create a new capsule after deletion. Locking does not clear a snapshot already unlocked in another tab.

TTL is fixed at seven days. Expired/malformed envelopes are purged on inspection/unlock; a running view schedules expiry. Closed browsers cannot run purge timers. Wrong passphrase or cryptographic damage returns no plaintext (a structurally valid locked record is retained because those cases cannot be distinguished). Unavailable WebCrypto/IndexedDB fails closed with an explanatory status. Missing Web Locks refuses save, inspect and unlock; deletion still attempts a committed IndexedDB clear and explicitly reports that cross-tab coordination was unavailable. This fallback cannot promise ordering against an older/non-cooperating tab's pending write. A rejected lock request fails the operation without an unlocked retry. Deletion is local only, with no sent remote copy; it cannot guarantee erasure of backups, caches, forensic remnants or user-made copies. Exact-origin binding prevents cross-origin replay, but cannot distinguish a copied record returned to the same origin/profile context, same-origin tabs, browser compromise or clock rollback. Offline guessing remains possible with a weak passphrase. No clinical effectiveness, clinician sharing, real-patient suitability or GDPR clinical deployment is established.
