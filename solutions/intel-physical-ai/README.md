An operator-led, **OFFLINE / SYNTHETIC** Inspect-to-Action Cell. Work ID

`51ac807d03fe5c37d1fdf8518ef32830ff50ac2b`. Independent prototype, no Intel endorsement.

## Run locally

Node 22+; no installation, dependencies, internet, camera or hardware required.
From this folder:

```sh
npm test
node cli.mjs serve
# Open http://127.0.0.1:4310 in a browser; Ctrl+C stops the local server.
node cli.mjs demo tests/my-receipts.json
node cli.mjs verify tests/my-receipts.json
node cli.mjs verify tests/demo-receipts.json
```

The server binds loopback only and serves five allowlisted product files. It has
no upload API, camera permissions, device adapters, analytics, external assets
or network clients. Its Content Security Policy denies browser connections.
Do not expose the local server to a network. No real camera input is collected.
Exports contain only built-in fixture data and operator step timings; imported
files are read locally, size-limited to 256 KiB, and never uploaded. No browser
storage is used. Download receipts to preserve them before reloading the page.
CLI output files use exclusive creation, so existing receipts are not overwritten.

## Operate the cell

1. Choose and load a labelled fixture. Labels are synthetic ground truth, not
   a routing shortcut. Two drawn cards show top and inspection views; a dashed
   region marks the supplied anomaly where one exists.
2. Evaluate the anomaly gate. Score and uncertainty are invented deterministic
   values, not model probabilities or calibrated statistical intervals. Good
   requires the **entire** interval below 0.50; defect requires the entire
   interval above 0.50. Touching the threshold cannot pass.
3. For uncertainty, replay the inspection once or acknowledge manual review.
   Replay uses the same capture, never adds evidence or improves confidence.
   Manual review can propose **hold only**. It cannot override stops or pass a
   part as good. A separate placement button is still required.
4. Simulate bowl placement. Good / defect / hold are software destinations;
   there is no robot action or automatic placement. Stop is always available
   before terminal completion. Load a new episode to restart.
5. Download the receipt. Load that JSON to verify and reconstruct every step.
   Invalid imports leave the current episode intact.

Six deterministic fixtures cover clear good, scratch defect, uncertain hold,
exact threshold hold, low confidence, and missing inspection camera. Confidence
below 90%, either missing camera, manual stop, or age **greater than 30,000 ms**
stops the episode without a bowl. Every operator action checks freshness again.
The browser uses a monotonic local timer and a periodic stale check; browser
suspension can delay rendering, but the next action still checks elapsed age.
CLI uses explicit virtual milliseconds, not physical capture timestamps.
Receipt replay restores that virtual age; it does not claim new real evidence.
Terminal completion cannot be undone by another step.

## Evidence and integrity

`core.mjs` contains fixtures, policy and the pure transition logic shared by UI
and CLI. Input digest = SHA-256 of canonical version + fixture + policy. Every
step records command ID/type/virtual time, resulting state, producer/version,
sequence, previous hash and its own SHA-256. Receipts explicitly carry
`SYNTHETIC`, `actuation:false`, `inference:false`. Import reconstructs the
built-in input and all commands, then compares the entire computed receipt.
Unknown fixtures, mutated state/policy, backward clocks, conflicting command IDs
and altered receipts fail. Identical command retries are idempotent. Hashes are
unsigned corruption checks, **not authenticated provenance**: anyone can author
another valid synthetic trace. Reproducibility depends on this version's pinned
fixtures and policy. Example receipts are generated by `node cli.mjs demo`, not
hand-edited. No measured throughput, accuracy, inference latency, power or
thermal claim is made; elapsed virtual timings are not a hardware benchmark.

Focused verification on Node v26.13.0: 15 tests passed with
`node --test solutions/intel-physical-ai/tests/*.test.mjs` from repository root.
CLI generated three receipts (good, defect, hold), then verified them. Browser
rendering, accessibility with assistive technology, real camera and all sponsor
hardware/provider behavior remain **not tested**. UI includes visible labels,
keyboard-native controls, focus outlines, live status, responsive layouts and
text alternatives; these are implementation features, not an accessibility audit.
