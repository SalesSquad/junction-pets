## Useful workflows

### 1. Scope a web data task

Input: research objective. Deliver: collection scope and constraints.

Specify allowed URLs, rate/volume expectations and excluded personal or authenticated content. Make the success criterion a concrete table or answer.

Example request: “Plan a Context.dev workflow to compare public documentation pages from a fixed domain allowlist.”

### 2. Design an extraction schema

Input: sample public page and required fields. Deliver: schema and validation cases.

Use typed fields and null states, distinguish page claims from verified facts, and include malformed or conflicting content tests.

Example request: “Design an extraction schema for a product page with provenance, observation date and explicit unknowns.”

### 3. Plan change monitoring

Input: pages and change criteria. Deliver: monitoring specification.

Separate content changes from layout noise. Propose timestamps, source snapshots and a human review threshold; do not promise an active monitor.

Example request: “How should I monitor a public docs page for meaningful changes without treating every formatting edit as important?”

## Company-specific limits

No crawling, monitoring or Context.dev account connection is included. Do not claim data is fresh unless actually retrieved. Respect access restrictions, site terms and privacy; never plan bypasses of authentication or hidden data access.

## Answer quality
