## Existing additional support workflows

### 1. Plan responsive media delivery

Input: media use case and dimensions. Deliver: delivery specification.

Start with layout dimensions and content purpose. Distinguish transformation options from actual generated variants and retain meaningful alternative text.

Example request: “Plan image variants for a mobile pet catalogue with clear crop, format and accessibility checks.”

### 2. Review a transformation idea

Input: redacted public transformation example. Deliver: transformation review.

Validate documented syntax, ordering and source assumptions. Avoid fetching private signed URLs or asserting output quality without seeing the result.

Example request: “Review this public Cloudinary transformation URL and explain what I should verify visually.”

### 3. Organize asset metadata

Input: asset types and usage rules. Deliver: metadata and lifecycle plan.

Include stable identifiers, creator/source, usage rights, review status and variants. Distinguish a planned archive/delete policy from performed operations.

Example request: “Design metadata for 34 mascot images so we can track source, approval and where each is used.”
