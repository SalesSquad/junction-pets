## Verified data pipeline

`scripts/craci/lens-real-bop.py` requires the exact ZIP digest and per-frame real PNG annotation alignment (`scene_gt.json` and `scene_gt_info.json`), rejects ZIP path traversal, invalid boxes, tiny crops and visibility below 20%, and extracts only four pre-registered object classes: `4, 6, 9, 15`. It streams real RGB camera pixels in local memory and derives 48 numeric features per crop (24 RGB histogram bins, 16 luminance cells, 8 edge-gradient features). It never writes image crops, OCR text, faces or device logs to Git/CRACI. This is a real-image downstream classifier experiment, **not a VLM/image encoder fine-tune**.

Real-world scene isolation is pre-registered before R learning: train source scenes `48,49,50,51,54,55`; calibration `52,53,56,57`; test `59`. Scene `58` is scanned but produces zero crops for the four selected object IDs, so does not appear in the feature CSV. Images from one source scene cannot cross the three partitions. The BOP original includes other scenes and classes; the source archive's held-out BOP test images are **repurposed** into our internal task. Consequently, these results **must never be presented as an official BOP leaderboard metric** or as evidence of identification on user-owned glasses.

Observed generation of the pinned archive: **1,255 labeled crops from 825 distinct real camera frames**. Partitions: 580 train, 375 calibration, 300 test. `fixtures/lens-public-ycbv-20261114` contains only `real-object-features.csv` (SHA-256 `c2374f53bc510b6655623f5fa05bb23d08bd1531f24b0aa4e2bcdccab11899a6`), `real-object-features.parquet` (`be31ea09fcbaeb2adb67cdcbd9a248b65bf5444defe293cbc48cf4c29c37b491`), and `admission.json`. Source rows carry real scene/frame labels, object class, visibility, image digest, and no private user details. Parquet round-trip matches all rows and columns.

`docs/CHIBI_LENS_DATA_SOURCE_REGISTER_20261114.json` labels each existing source as approved public, synthetic-only or quarantined. `scripts/craci/lens-data-gate.py` rejects private/synthetic status escalation and cloud training with missing/altered source provenance, incorrect MIT license, extra files, symlinks or bad SHA-256. No generic user-consent bypass exists. It permits only the exact public numeric features; it does not permit private images or raw pixels.

## Actual R training and evaluation

The existing **manual** CRACI `craci-pilot.yml` accepts new `lens-real-bop-train` workload, with 4 source-bound, 8-vCPU cells (32 vCPUs if all admitted concurrently). The four cells train genuinely different frozen feature profiles: `all` (48), `color` (24), `spatial` (16), `gradient` (8). Each cell fits `nnet::multinom` multiclass logistic regression and `rpart` tree to **real** annotated object crops, with a transparent nearest-centroid reference. Four object categories only; no false claim of unique physical object identity or authorization.

Calibrate each model's confidence threshold using calibration data only so wrongly accepted object suggestions are at most 5% of calibration rows; choose the model with highest correctly accepted coverage on calibration (a learned model does not automatically win). Test scene 59 is never used for model selection. Preserve every selected/unselected heldout metric: top-1, accepted coverage, wrongly accepted fraction, abstentions and per-class counts. A model is **not** promoted even if it wins this internal, single-scene heldout; no host policy, real wearable deployment or raw pixels are exposed.

CRACI network is `default: deny`, presets limited to GitHub/Ubuntu; dependencies installed only from Ubuntu apt; no cloud vision inference, new credentials, provider token or cash top-up. CSV+admission bytes are source-pinned in a task-owned Git branch. Every job uses the existing source-reported `run-receipt.mjs`, and publishes JSON/ZIP-only evidence with trained RDS and report; source-reported is NOT provider-signed attestation. Actual CRACI billing remains unknown. The global CRACI credit window still stops 2026-11-15 17:00 UTC independently.

## Hosted first-run failure and focused correction

[Source-pinned CRACI run #43632712936](https://github.com/SalesSquad/junction-pets/actions/runs/43632712936) at harness commit `f3a825d2a8aa46044dbf280b570c20a1e3441146` admitted all four 8-vCPU profiles. Ubuntu R dependencies and the exact public-source/license gate **passed**. All four R jobs later **failed** in prediction: `Error in FUN(X[[i]], ...): all(levels %in% colnames(scores)) is not TRUE`. The zero-label centroid comparator was computed using `vapply()` over unlabelled class indices and thus produced an unnamed probability matrix. This is an evaluation-code bug, **not** an evidence of poor real-image recognition performance. The failure receipts remain intact.

The focused fix attaches the exact pre-registered four class IDs to the centroid probability columns *before* the existing class membership/finite-probability assertions. It does not invent ground-truth labels, reorder fitted-model outputs, change source bytes/scene split, relax the calibration FPR limit, or alter the original provenance gate. New immutable harness HEAD and a fresh failed-path requalification run are required to claim successful R training.

**Key finding:** the 5%-wrong-accepted calibration gate on scenes 52–57 did **not transfer** to the entirely separate scene 59 for full (24.0%) or color (8.7%) profiles. The color profile's `EXPLORATORY_REAL_HELDOUT_GAIN` flag only indicates relative improvement compared to its own weak centroid baseline, **not safe deployability**. The independent audit applies a stricter, absolute heldout 5% wrong-candidate threshold; **0/4 model profiles qualify for promotion**. No runtime model, product integration, policy grant or external service was changed.

This is a deliberately small, internal **real-pixel** classification baseline (four object categories, one heldout scene). Multiple object crops from the same frame and one test scene make naive independent-example confidence intervals misleading. No official BOP challenge or live Meta glasses recognition claim is made. Future work should add new **independent real scenes and hard-negative object classes**, benchmark camera/lighting variation, and compare against real frozen Vision/Core ML embeddings, with any private field data remaining local unless explicitly consented and licensed. Increasing compute on the same heldout scene alone would promote overfitting.
