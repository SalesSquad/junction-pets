# Junction 2026 — submission boundary and challenge policy

This is the **Junction pet-agent monorepo**, not the private Chibi.pet Marketplace/Runtime source. A demo may be hosted or reached through Chibi.pet, but the code handed to judges must be the auditable agent work and its self-contained public interface, reproducible checks and safe demo instructions.

## Preserve the IP and consent boundary

**Included in a future reviewed submission:** selected `pets/` agent packages and their original source citations, safe instructions, user-controlled agent workflows, synthetic fixtures, tests, portable adapter interface, and a demo running without private credentials.

**Not included:** `SalesSquad/chibi` source, private creator/recipient records, payment/subscription data, Passport memory, OAuth secrets, private training data, undeclared partner assets, and the internal Mission Control work registry/receipts/worker schedules.

Any public export must be deliberate and separately reviewed. The repository is currently **private**, and this document does not authorize a change in visibility, a license grant, a submission, or a production release.

## Challenge participation and disclosure

Do not equate the 34-company **partner roster** with 34 challenges that can be submitted to. Different partners include technology, challenge, main and collaborator roles; actual challenge eligibility and individual rules need checking on the Junction submission platform. The published 2026 general terms include a one-team-per-challenge rule and require clear disclosure of code created before the event. Technology challenges may be combined with a main challenge, but the ability to enter all challenges has not been verified.

The work originating before Junction — Chibi.pet runtime, Marketplace, existing companions, and earlier source work — must be disclosed. Judges must see the *new, demonstrable work performed for the selected challenge*, its source, input/data permissions, measurable outcome, replayable demo, and honest limitations. Do not claim that a prepared JSON persona is a running AI agent.

The event's public messaging mentions open source/MIT; check the current challenge-specific terms and repository release scope before making any source public. Retained private runtime code is not part of the competition repository.

## Per-challenge submission checklist

- [ ] Confirm the exact challenge brief, sponsor, category, eligibility and allowable number of submissions in the Junction platform.
- [ ] Identify one real user, one problem, one measurable task and at least one failure/recovery case.
- [ ] Demonstrate the pet actually completing a useful flow, with a real host or clearly disclosed simulated provider.
- [ ] Run the authored behavioral cases against the chosen model; attach source-bound results (not just the 204 case definitions).
- [ ] Pin the pet version, source SHA, model/adapter, runnable tests and a short reproducible setup.
- [ ] Provide a usable demo link or short video with no secrets or sign-in traps; show the Chibi host boundary accurately.
- [ ] Disclose every pre-existing component and source license; audit company logos, brands and external assets separately.
- [ ] Review the public export tree to exclude `ops/`, secrets, internal receipts and any Chibi private source.
- [ ] Get the required owner decision before making a private repo public, submitting, deploying or granting a new license.

This checklist is a release gate; passing ordinary unit tests does not constitute eligibility, license review, browser/device proof, runtime availability or successful submission.
