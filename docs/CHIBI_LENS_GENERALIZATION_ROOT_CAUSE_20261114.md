## Reproduced reasons the prior 8+3 R experiments failed

1. **Effective sample size was much lower than 525 images.** Training used only four physical YCB-V source scenes. A source video contributes many correlated frames, so treating every object crop as an independent learning example inflates confidence. The 225-crop heldout was only three physical scenes.
2. **The heldout labels were nearly perfectly entangled with the scene.** In that three-class YCB-V study, separate test scenes 56,57,58 each held a different target class (1,12,3); a model could learn colors/camera surroundings rather than visual semantics. Scene-heldout did not mean class-balanced heldout. The previous 4-class source heldout was also only a single scene.
3. **Feature representations were too weak.** Old models used 48 simple color/spatial/gradient measurements on cropped pixels, with no frozen semantic image backbone. Background may remain inside visible bounding rectangles; the model could exploit contextual shortcuts.
4. **Empirical <=5% calibration wrong-accept was overinterpreted.** Under physical scene shift, the original all-feature R model still made **72/300** accepted-wrong predictions, color **26/300**. The second R8 study's eight variants had no safe holdout result. Its R3 classwise exact risk-bound lowered wrong accepts from 62 to 49 of 225, but correct accepted fell from 149 to 78; metadata Mahalanobis shield worsened wrong accepts from 62 to 72. A binomial bound estimated on one calibration scene cannot guarantee low error on another.
5. **Volume of CRACI jobs was a proxy for productivity, not quality.** The observed eight and three CPU cohort runs were source-verified and technically green; these are workflow successes, not demonstrated model improvement.

These findings are derived from exact immutable results: [R8 training #43635307560](https://github.com/SalesSquad/junction-pets/actions/runs/43635307560), [R8 remaining #43635610887](https://github.com/SalesSquad/junction-pets/actions/runs/43635610887), and R3 [#43636400308](https://github.com/SalesSquad/junction-pets/actions/runs/43636400308) / [#43636605103](https://github.com/SalesSquad/junction-pets/actions/runs/43636605103), preserved in PRs #177/#178.

## Four useful experiments instead of repeated green cohorts

The manual CRACI workload `lens-hb-vision` has four CPU-4 candidate model arms:
1. `color`: old train-normalized color histogram logistic baseline, 3 decay variants.
2. `vision_prototype`: train-only normalized Vision class prototypes, 3 pre-registered similarity/margin variants.
3. `vision_pca`: train-only PCA of Vision embeddings (8/16/32 components) with regularized logistic regression.
4. `vision_guard`: train-only Vision PCA + image-embedding prototype similarity OOD gate, before calibration confidence.

**One original color baseline is refitted identically in each source-bound arm**, to compare on exact splits. Each candidate has three parameter settings chosen **only** on physical calibration scene 10, requiring no more than `floor(.05 * 234)=11` accepted wrong proposals across both known misclassifications AND unknown objects. No final heldout labels enter model fits, thresholding or candidate selection. The immutable physical test scene 11 is evaluated only after fitting/selection. Unlike the prior scripts, unknown object false acceptance and known-object coverage are both first-class outputs, alongside abstentions, per-object ground truth and a *frame-clustered* exploratory bootstrap interval (not an IID guarantee or provider attestation).

A model can earn an **exploratory** diagnostic flag only if in the never-before-used scene 11 it admits at most `floor(.05*235)=11` wrong object proposals, has <=5% unknown-item false accepts, captures >=20% of known objects correctly, and is not worse than the color baseline. **No hosted result automatically promotes or deploys a model.** One physical heldout scene and correlated video frames cannot establish wide-world performance, biometric identity or host tool authorization; further new field scenes and a real object detector are needed.

The standard source-bound CRACI result uses 4×4 vCPU (20-minute hard caps), with one `pilot` arm first and three new `remaining` arms only after the pilot has actually qualified. ## 14 Nov source-defect correction: calibration selector chose a useless zero-coverage baseline

Source-bound first HB hosted pilot [#43640473902](https://github.com/SalesSquad/junction-pets/actions/runs/43640473902) and three other models [#43640703367](https://github.com/SalesSquad/junction-pets/actions/runs/43640703367), original HEAD `3f8d57cbd47e07be97137e03121205248e88d56f`, completed technically with source-verified model receipts but all four **selected the baseline**. Its calibration: 0 correctly accepted / 0 wrong and **234/234 abstentions**; heldout: 0/235 accepted, 0 correct and 0 wrong. This is not an effective recognition model.

**Reproduced source bug:** R first sorted model candidates by highest correctly accepted count and THEN rejected only the top candidate if its wrongly accepted count exceeded the baseline's zero. It never considered the other already-calibrated variants. The hosted calibration metrics show `vision_prototype`: best top candidate 80 correct / 6 wrong, but **second** candidate 56 correct / 0 wrong; `vision_guard`: top candidate 81 correct / 3 wrong, but **second** candidate 56 correct / 0 wrong. The old selector rejected the top candidate and incorrectly returned the useless baseline in both cases.

**Focused fix:** `scripts/craci/lens_hb_selector.R` filters **all** three pre-registered candidates first by (a) <=5% calibration wrong-accept, (b) no more wrongly accepted than the original baseline, (c) strictly more correctly accepted known samples, and (d) >=20% calibration known-object coverage. It THEN ranks eligible candidates by accepted correct descending, accepted wrong ascending and stable source index. Thus the existing pre-registered safety rule is **not relaxed**. The source-bound R test `scripts/craci/lens_hb_selector_test.R` covers the two observed 56/0 cases, all-unsafe fallback, zero-utility fallback, nondegenerate baseline and malformed scientific counts. The new opt-in `lane_slice=selection-repair` checks **only** `vision_prototype` and `vision_guard`, not the two unchanged green paths; all four original results remain preserved under the original exact SHA.

**Do not overstate this repair.** The original heldout scene 11 had already been reported for the (uninformative) baseline. Any fresh result from the corrected source is explicitly labelled an exploratory **source-defect retest**, not a newly blinded validation or proof of real-world camera accuracy. No model is deployed or allowed to trigger identity/consent/action permissions. A new physical scene with independently sourced known and unknown objects must be acquired for final external qualification. Source-reported GitHub receipts are not provider-signed attestations; cost remains unknown.

## One coordinated qualification path (instead of endless CRACI repeats)

**Gate A — true independent training evidence.** Build a provenance-checked corpus of multiple REAL physical scenes with BOTH known object categories in every necessary split, plus several physically unknown classes never used in either training or calibration. Split by **scene + video + device**, not random neighboring frames. Record lighting, occlusion, camera, duplicate/perceptual hashes and object counts. New sealed holdout objects/scenes must never be inspected during feature selection, threshold tuning or failure triage. Do not infer training rights for personal/family/screenshot footage; use public appropriately licensed sources until explicit capture consent exists.

**Gate B — actual product-meaningful vision stack.** Replace ground-truth BOP visible masks and annotated object boxes with an actual detector/segmenter running on frames; output candidate regions, their uncertainty, immutable source IDs and embeddings. Compare Apple's fixed Vision FeaturePrint backbone with an appropriately licensed stronger visual encoder, and train only small adapters on real labelled data as the data supports. R owns risk/coverage calibration and source-aware statistical tests; CRACI owns bounded CPU hyperparameter experiments. GPU retraining only when independently measured gains justify it. Track true object detection and class/instance re-identification separately; never treat a BOP class label as an identity or authorization credential.

**Gate C — quality gates with both sides measured.** Use absolute false accepted suggestions, false positives on never-seen unknown objects, accepted precision, known-object coverage, per-scene worst case and frame/scene-clustered confidence intervals. A zero-acceptance model MUST fail the **utility gate** even when its false positive count is zero; a high-coverage model MUST fail the **risk gate** when unknown objects are wrongly accepted. Pre-register goals for the field pilot (e.g. >=97% accepted precision, >=80% known-object coverage, <=1% accepted unknowns, with confidence intervals and per-environment reporting). These are PROPOSED targets, not evidence already achieved. One 48-frame heldout scene is insufficient to certify them.

**Gate D — sealed evaluation then deployment decision.** CRACI's eight lanes can test eight genuinely distinct model/data hypotheses with source-pinned receipts, storing failed and negative work; only the best data-qualified candidates progress. Freeze source, preprocessing, weights and thresholds **before** one fresh sealed benchmark and authorized real-device shadow test. Publish actual risk-coverage curve and latency/memory on supported Apple devices. Production model upgrades, permissions and release require separate authority; no implicit rollout from a green GitHub workflow.

**No automatic repetition** of the now-green old 4+2 source runs, the synthetic 8+12 runs, or previous R8+R3 BOP studies. The next scientifically decisive run is new independently sourced, licensed scene+unknown data with an actual candidate detector, not another calibration retuning on the same scene 11.
