# Chibi Lens full-frame source integration: three P2 gate repairs

Work ID: PORTFOLIO-CHIBI-FULLFRAME-20261115. The nine source files from original stacked [PR #208](https://github.com/SalesSquad/junction-pets/pull/208) commit `2e338f72ac6e912b23b38b66526c2cb645852868` were imported byte-exact onto main after old #190 dependency had already been integrated through PR #201. Original proposal code, Swift adapters and negative HB source smoke remain source-exact; model training/weights/physical product operation from PR #215 are not included.

Independent read-only review of the nine-source-file snapshot identified **three reproducible P2 qualification-integrity defects**, without an independent provider attestation or production action:
1. `lens_field_gate.py` compared unknown and known class lists with direct Python sets. A numeric class 23 on one side and its string `"23"` encoding on the other silently bypassed disjointness. The repair canonicalizes bounded nonnegative numeric IDs and symbolic IDs into a common class representation, rejects unknown types, booleans, duplicates and collisions, and retains the original rejection reason `UNKNOWN_CLASSES_NOT_EXCLUDED_FROM_CALIBRATION`.
2. Correctly accepted known object counts could exceed the number of **actually detected** IoU≥.50 true positives. The repair requires `known_correct_accepted <= detector_true_positives_iou50 <= annotated_detectable_objects` for **every** physical scene. Impossible data now fail closed with `ValueError: Inconsistent real-world confusion or localization counts`. An existing low-detector-recall unit fixture was updated to a *physically possible* low-recall case; the scientific threshold was not lowered.
3. Frame SHA and capture identifiers excluded the same exact frame/capture but did not forbid use of a *different capture of the training/calibration physical scene*. Field receipts now **require** nonempty, bounded, duplicate-free canonical `frozen_fit_scene_ids`; any `scene_id` colliding with that set returns the new reason `TRAIN_CALIBRATION_PHYSICAL_SCENE_LEAKAGE`. Missing scene-level fit provenance returns `MISSING_OR_INVALID_FIT_SCENE_PROVENANCE`. Older claims missing this field must be **rejected**, not grandfathered in.

Three targeted new negative tests show the previously admitted mixed-type class overlap, impossible detector counts, and reused training scene are rejected; all historical positive/privacy, Wilson/group, GT/input, and unknown-class negative tests remain. On this integration source: **19/19 field-gate tests, 11/11 GT-separated proposal/Iou tests, 3/3 Swift macOS typechecks, Python syntax PASS**, no skipped checks; independent reviewer rerun of repaired source follows separately. The original six #208 fault cases from PR #220 are pinned to the **old** original SHA and remain valid historical evidence, not a qualification of the repaired bytes. No new real image data, device/GPU/OCR/paid model calls, model weights, provider spend, production permissions or deployment were added.

This gate only validates **source-reported** statistics. Scene IDs alone do not constitute cryptographic proof that locations/devices are independent; authenticated source/capture provenance, rights-cleared independent domains and a properly trained detector are still needed. Original HB full-frame smoke found 0/15 detections: the field model is **SCIENCE RED** and cannot identify people/objects on live glasses or authorize agent actions. #215 remains an active separate owned detector source branch.
